The report contains timestamps, browser capability hints, controller and existing root/Stage 1 registration script paths/states, active/waiting/installing states, recognized versioned app cache names, static request paths, method, response status/type, and presence-only authorization-header flags. Unexpected asset URLs/query values and sensitive exception text are omitted. It lists only existing app/Stage 1 cache names, opens those for metadata reads, and never reads response bodies, IndexedDB records, sessions, scores, API data, cookies or header values. It does not register/update/unregister workers or add/delete/put cache data. It makes no network/API calls itself; ordinary page navigation still uses Safari's normal network/worker behavior.

An active script URL does not encode the installed worker's VERSION. The report deliberately separates activated registration state from cache version: it can establish which versioned static cache exists and whether another worker is waiting, but does not directly read the running worker's source code. Do not claim a previously unobserved waiting transition occurred based only on a later cache snapshot. Retain this limitation in acceptance results.
