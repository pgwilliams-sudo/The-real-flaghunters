## 4. Stage 7 operating configuration

- Set `V2_SCORING_ACCESS_MODE=pin-free` and `V2_SCORING_ACCESS_REVISION=1` explicitly for the first release. These also match the current defaults. Admin creates the round, saves groups, then uses **Select Comps & Start Round**. Start is tied to the saved group version. On an ambiguous start, keep the same choices and retry the same operation once after checking status. New V2 group scoring requires an admin start.
- PIN-free group selection opens a scoped scorer session without generating or asking for a PIN. A session can save, correct with a reason and finish its group. Audit records capture role, credential and operation, with no individual identity claim. Apps Script authorises each request independently of the frontend. Round setup, competition configuration and draws, admin journal recovery, and reveal require an admin session from a unique, password-manager-generated `V2_ADMIN_SECRET` of at least 32 characters. Scorer sessions expire after 30 days and admin sessions after 12 hours.
- Keep `group-pin` dormant for production unless the owner approves a switch. Pause scoring, reconcile or export each device's pending saves and record the current mode/revision. Change the mode and increment the revision together in the controlled window, including on a switch back. Old scorer sessions fail on reconnect. In PIN mode, admin issues a two-digit group PIN privately to each scorer, who reopens online before going offline. Keep rejected requests under their original scope for review. Group PINs are lightweight access control and leave public GET visibility unchanged.
- Admin alone may execute **Reveal final clubhouse results**. The backend recovers accepted pending server operations, requires every group to finish and every player to have an entry for all 18 holes, and requires the Blind Pairs draw if enabled. It writes `revealed_at` and `locked=true` together under the script lock. The release operator additionally checks every scoring device because the backend cannot see all IndexedDB queues. All score and round edits stop permanently after reveal, including admin corrections. [Stage 7 scoring and setup](PHASE3_STAGE7_RESULTS.md) · [Reveal and public results](PHASE2.md)

## 7. Residual risks and stop rules

| Risk | Consequence and response |
| --- | --- |
| Anonymous production scoring and reads | An **Anyone** web app can be called directly by someone with the endpoint and valid group selection. PIN-free users can obtain group-scoped sessions, browse that group's full scoring/history and change or finish it before lock. Public GET includes players and groups, potentially exposing names and handicap data, and gives the supported results views. Public leaderboards hide holes 16–18 before reveal. A private Site does not restrict direct API access or provide personal attribution. Unsolicited writes or quota usage are possible. Explicitly approve this exposure and the minimum inputs or hold the release. |
| Offline conflicts, eviction and delayed acknowledgements | Stale revisions can reject after reconnect, credential changes can strand requests for review, and browser storage can be evicted. Durable local saves plus operation IDs reduce loss and duplicate acceptance. Use the paper card, original IDs, server history and private recovery exports to establish the accepted state. Escalate missing or ambiguous data before changing mode, fallback or reveal. |
| Permanent lock | Reveal finalises the application record irreversibly. A scorer's empty queue cannot prove every device is clear. Incorrect or late scores after lock are an incident to document. Restrict direct Sheet and Script editor access because a privileged Google editor is outside app-level lock and audit controls. |
| Accidental production writes | The development connector, same-account workbook access, manual Script property edits and optional first-write tab creation can defeat an informal separation. Use distinct IDs, origins and identities, fixed endpoint binding, explicit schema readback and one writer app. Stop on any environment mismatch or unknown effective grant. Preserve V1 and both locked test workbooks. |
| Service availability | Apps Script quotas, golf course connectivity, Safari delays and invitation/session problems can interrupt a round. Confirm preparation and audience on the actual device, keep one support contact and fall back to the paper card or working V1 without parallel submissions. |
